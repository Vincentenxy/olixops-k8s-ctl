## 文件下载第二阶段（本次只记录，不实现）

当前方案：主 MCP 准备用户和 Pod 绑定的下载引用，认证 HTTP POST 流式输出单个文件，本地 curl / 辅助客户端落盘；不设固定文件大小上限。不会把下载字节放进模型上下文。以下能力尚未实现：

- [ ] **并发问题**：面向数百开发者压测；确定全局、用户、目标 Pod 的下载并发配额、排队、限速、取消与公平性，避免大量 exec 占用 API Server 和服务连接。终端会话配额不等于下载并发配额，现有 4096 条待领取引用上限也不等于下载并发控制。
- [ ] **大文件问题**：对 GB 级文件、慢连接、网关缓冲/超时、API Server 长连接、服务内存与带宽、本地磁盘耗尽进行专项验证；设计观测、超时、流控、进度反馈和失败清理，不因当前无大小上限就宣称任意大文件已通过验收。
- [ ] **断点续传**：本版 Range 直接拒绝；后续设计偏移、文件版本绑定、引用续期、失败重试与 HTTP 语义。当前失败必须重新准备并从头下载。
- [ ] 文件完整性：读取期间文件变化的检测、远端哈希或快照、一致性确认；当前辅助客户端只有本地 SHA-256，不能独立证明远端文件未变化。
- [ ] 多副本路由和引用存储：当前内存引用只在单实例有效，尚无共享存储、会话粘滞或故障恢复。
- [ ] 目录和归档下载：当前只支持单个普通文件；目标无 tar 时返回失败，不自动安装工具。
- [ ] 在权限阶段统一处理归属、路径与符号链接策略、下载审计和敏感文件策略；本次保留现有认证、grants、范围、Pod UID 和默认放行拦截扩展点，不新增权限模型。
